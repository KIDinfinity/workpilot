## ④ 结论

1. **分块**：`hit@5` 在 c600_o0 / c600_o100 / c1000_o0 / c1000_o100 上并列 0.921，
   `hit@1` 六个变体全部 0.737 —— 评测集区分度不足，分块差异只体现在 MRR 的名次位内。
   c300 系列（1737/2221 chunks）hit@5 掉到 0.895/0.868，语义碎片化，否决。
2. **top_k**：k=3 误拒率 0.211 明显偏高；k=5 与 k=8 误拒相同，但 k=8 成本 +42%，
   故取 **k=5**。
3. **最终配置为 c600_o100 + dense + top_k=5**：与 c1000_o0 的 hit@5 持平（0.921），
   MRR 低 0.013（一个名次位内），但库内误拒率 0.132 vs 0.158、生成成本 ¥0.0407 vs
   ¥0.0538（-24%）。误拒直接损伤可用性，优先于 MRR 的微弱优势。
4. **hybrid 未采用**：hit@5 0.921 → 0.816、hit@1 0.737 → 0.605、MRR -0.085，
   且无任何一题变好。

- q005「新增环境变量要遵守哪些规则」（tags: standard/config）：#4 → 未命中

- q033「Pydantic 请求体外面再包一层键名」（fastapi）：#5 → #7
- 反向变好：0 题

原因：fastembed `Qdrant/bm25` 是英文分词，中文 query 切不出有效 token，sparse 通道
召回质量差；RRF 把 dense 的强排序与噪声按名次等权相加，反而稀释了原本正确的 top1。
中文场景要混合检索，需换中文分词 sparse 编码器（jieba 前置 / `bge-m3` 自带 sparse）
并改用加权分数融合，列入 W6 待评估。
