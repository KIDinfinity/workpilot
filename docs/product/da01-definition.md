## 0. 一句话

为**我自己（在职前端/全栈）与同类小型研发团队**，在**「查团队规范 / 查组件库用法 / 让 AI 按规范写代码」**场景中，用**带引用的知识问答（Grounded Q&A，先 RAG 后接 Agent 自检）**解决**规范与用法散落在多人多处、通用 AI 又不懂团队上下文**的问题，每周节省 **≥ 60 分钟**。

---

## 1. 八要素

| 要素     | 内容                                                                                                                                                                                                             |
| -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 问题     | ① 内部组件库文档不完整，写页面时要全局搜代码 → 翻 3–5 个文件看别人怎么写 → 不行就问同事（P-02：5 次/周 × 15 分钟 = 75 分钟/周）；② 通用 Copilot/ChatGPT 不懂团队规范（API 前缀、错误处理、权限校验），每次生成后要手改 3–5 处，漏改就被 CR 打回（P-07：8 次/周 × 5 分钟 = 40 分钟/周）。合计 **115 分钟/周**损失。 |
| 用户     | 主：我自己（5 年全栈/前端，在职）；次：3–20 人小型研发团队（新人与老人重复问答、规范不统一）。                                                                                                                    |
| 场景     | 主场景 **SP-A 深化**：输入 = 自然语言问题（「这个组件怎么用」「提交前要检查什么」「接口错误码怎么处理」）→ 输出 = 带段落级引用 + 出处链接的答案，知识不足时明确拒答。基线 = SP-A（本场景即 P1 核心链路的深化版）。 |
| 价值     | 115 分钟/周 × 节省 60% ≈ **节省 69 分钟/周**（保守下限按 **≥ 60 分钟/周** 记）。                                                                                                                                    |
| 验证方式 | W5：50 题评测集（hit@5 / 引用正确率 / 库外拒答率），题目从痛点 P-02、P-07 的真实问题改写；加「自用 ≥ 30 次」的真实使用日志（脱敏语料）。                                                                            |
| 交付形态 | Web Console（流式 + 引用面板）+ REST API（`/v1/kb/ask`）+ CLI；W13 起通过 MCP 嵌入 IDE（写代码时直接查规范）。                                                                                                    |
| 商业模式 | 开源核心（MIT）；Pro Kit 一次性买断（生产部署包 + 本场景包 + 评测模板 + 部署手册）。                                                                                                                              |
| 技术组合 | M1 LLM Gateway（W2–3 ✅）+ M2 RAG（W4：Ingest/Chunking/bge-m3/Qdrant/Grounded Answer）+ M3 Eval Kit（W5）。**不需要** M6/M7（工具与 Agent）——本场景只用检索即可闭环。 |

## 2. 成功指标

- 产品：每周节省 **≥ 60 分钟**（下限；W6 起用自用日志校准，可上调到 ~70 分钟）
- 使用：自用会话 **≥ 30 次**，有日志可查
- 质量：hit@5 **≥ 0.85**、引用正确率 **≥ 0.80**、库外拒答率 **≥ 0.80**
- 性能/成本：P95 **< 8s**、单次 **< ¥0.02**

> W5 拿到基线后允许调整（调完写 `plan/CHANGELOG.md`），但必须「有数字」。

## 3. 明确不做（v0.x–v1.0）

1. 不接入公司真实系统、不把公司机密代码 / 文档 / 工单送进外部 LLM API（蓝图 §8 红线）。
2. 不做通用聊天助手（没有知识库依据的问题一律拒答，不硬答）。
3. 不做模型训练 / 微调（全部用 prompt + 检索）。
4. 不做 P-03（PR 提交前自检）——那是 pre-commit hook / CI 脚本能解决的**自动化**问题，AI 适配度仅 2 分，本阶段不投入。
5. 不做 P-01 / P-04（需求分散、生产排障）——数据只能来自公司内部系统，硬门槛 D 不过（D 打 1–2 分），进 Backlog 不排期。
6. 不做 Agent / 工具调用 / 多步规划（M6/M7 留到 W9+，本场景不需要）。
7. 不做多租户登录、权限、审计（v1.0 之前不做，W19 再说）。
8. 不做移动端、不上 Kubernetes。
